# 可交换债公告情报整理

把一堆杂乱的公告 PDF（发行公告、募集说明书、追加担保、停止换股摘牌、半年报…）
变成一张可以直接粘进《每日可交换债公告整理.xlsx》成品大表的结构化表格。

**这个 skill 是「AI 精读 + 脚本排版」的组合**：提炼和纠错必须由模型读 PDF 完成，
脚本只负责校验和格式化。不要把提炼环节也试图脚本化 —— 条款散落在 PDF 各处，
只有读懂才能判断哪些是本次事件的关键信息。

> **SSOT 声明**：摘要规范与精读提示词的唯一事实来源，是本 skill 目录下的 **`prompt.md`**。
> 平台 `app/projects/anno.py` 运行时读取它（按 mtime 缓存，改完下次精读即生效）；
> 精读时它原样下发给执行方，所以两边看到的规则**天然一致，不存在抄写漂移**。
> 本文件**不再另抄一份**摘要规则，只保留骨架 / 反例 / 自检清单。
> **改摘要规范 = 改 `prompt.md`**，一处生效，无需再手工同步。

## 完整流程

### 第 1 步：转储 PDF

```bash
pip install -r requirements.txt
python scripts/pdf_dump.py D:\Anno            # → D:\Anno\_txt_dump\*.txt
python scripts/pdf_dump.py D:\Anno --clean    # 转储前先清除原有 txt（默认开启）
```

脚本会明确报告哪些是**扫描件（无文本层）**，并自动用 pypdfium2 渲染成 PNG 存到
`_txt_dump/<名>_pages/`。精读时模型读取这些图片识别文字，无需人工逐页看。

### 第 2 步：精读并填 JSON

逐份读 `_txt_dump/` 里的文本，为**每份公告**产出一行，写入 `input.json`（格式见
`example_input.json`）。9 个字段：

```
公告日期 | 上市公司 | 可交换债 | 证券代码 | 标的股票 | 股票代码 | 换股价格 | 公告性质 | 内容摘要
```

## 【摘要写法】权威正文在 prompt.md，本文件不另抄

摘要规范的**唯一事实来源是本目录的 `prompt.md`**（其 `SYSTEM_PROMPT` 段）：主线、
字数区间、四类公告模板、顺序铁律、8 条硬性规则，全在那里。平台运行时读它，
精读时随 prompt 原样下发——**执行方看到的规则与平台天然一致，不会再有两份抄本各自演进**。

**要改摘要规范，改 `prompt.md` 即可**，一处生效。本文件下面只保留便于人工比对的
填空骨架、真实翻车案例与提交前自检清单。

### 填空骨架（定期报告照抄此序）

```
<发行人><期间>营收 X 亿元（同比±Y%），净利润 Z 亿元（同比±W%）；总资产 A 亿元、
负债 B 亿元，资产负债率约 C%（较年初±D pct），经营现金流 E 亿元；<逾期/诉讼/受限资产
等风险点>。<一句风险判断>。本只<EB简称>（<代码>）余额 F 亿元，最新换股价 G 元/股
（<调整原因与生效日>），累计换股 H 股，担保比例 I%，<下修/赎回/回售是否触发>。
```

事项类骨架：

```
<主体>于<日期>披露<事项>：<关键金额/比例>；<关键日期节点>。<对 EB 违约风险或换股
保障的影响判断>。涉及<EB简称>（<代码>）……
```

### 反例 vs 正例（真实翻车记录，2026-09-01）

❌ **坏例**（25紫金E1 半年报，实际产出）：

> 紫金矿业投资(上海)有限公司2025年非公开发行可交换公司债券(第一期)'25紫金E1'（代码117239.SZ，深交所私募）半年度情况：发行规模7亿元、期限至2028-09-11、票面0.01%，标的股票紫金矿业(601899.SH)。受标的股价持续低于换股价90%影响，2026-04-24换股价格由7.32元/股下修至5.75元/股；预备交换股票市值/余额比115.46%，担保充足，赎回/回售条款未触发。财务（合并）：总资产105.20亿、负债66.51亿、资产负债率约63%；营收341.76亿（同比+10.7%），净利润-3.41亿（上年同期-0.38亿，亏损扩大）。

判废三条：① 段首是规模/期限/票面/代码/标的，纯基础条款；② 财务被挤到末尾当补充；
③ 净利亏损扩大 8 倍这种核心风险信号，通篇没有一句风险判断。

✅ **好例**（同素材按骨架重写）：

> 发行人紫金矿业投资(上海)2026上半年营收341.76亿元（同比+10.7%），净利润-3.41亿元（上年同期-0.38亿元，亏损显著扩大），总资产105.20亿元、负债66.51亿元，资产负债率约63%，盈利端持续承压、自身造血不足以覆盖债务。短期兑付依赖股东支持与质押物变现，流动性偏紧。本只25紫金E1（117239.SZ）余额7亿元，因标的股价持续低于换股价90%于2026-04-24由7.32元/股下修至5.75元/股，预备交换股票市值/余额比115.46%，赎回、回售条款均未触发。

### 提交前自检清单（逐条打勾，缺一不改完不许提交）

- [ ] 摘要**第一句**是财务或风险，而不是"发行规模 X 亿元、期限 X 年、票面 X%"？
- [ ] 定期报告类有没有那句**明确的风险判断**（短期违约风险较低／流动性偏紧／资不抵债…）？
- [ ] 字数落在对应区间？（定期 200~250 ／ 发行 300~360 ／ 事项 100~200，总区间 130~360）
- [ ] 一份报告涉及**多只 EB 是否已拆行**？每只的换股价、代码、担保比例是否逐只核对？
- [ ] 「上市公司」列是否**留空**？有没有误填标的股票名或发行人集团名？
- [ ] 日期是否**点分格式**（2026.8.31）且全表统一取 PDF CreationDate？
- [ ] 代码后缀是否符合 117xxx.SZ ／ 137xxx.SH ／ 132xxx.SH？
- [ ] 换股价格是否带「元/股」？

## 字段填写细则

「上市公司」列只填"发布公告的上市公司本身"，仅当上市公司代其控股股东/实际控制人披露时才填；绝大多数 EB 发行人是母公司/集团（非该列主体），故留空，对应标的股票在「标的股票」列单独填。成品表自身约 96% 行该列也为空，属正常设计，非漏填——不要因为该列空就去补发行人集团名或标的股票名。

一份报告常对应多只 EB（如广东能源半年报同时涉及 25粤能源EB、26粤能源KEB、26粤能源EB），
**每只 EB 单独一行**，发行人财务部分可复用，但换股价、代码、担保比例必须逐只核对。

### 第 3 步：生成

```bash
python scripts/build_anno_xlsx.py input.json                  # 校验 + 生成
python scripts/build_anno_xlsx.py --check input.json          # 只校验
python scripts/build_anno_xlsx.py input.json --strict         # 有问题拒绝生成
```

自动校验：必填字段缺失、摘要字数越界、**重复行**（同一只债 + 同一公告性质出现两次，
这是整理大批量时最容易犯的错）。默认输出 2 个 Sheet：`Sheet1` 整理表、`处理说明`；
`条款长摘要（原版）` 页默认不生成（仅当某行填了「条款长摘要」字段时才生成）。

## 桥接模式（EB-Agent 平台）执行规范

平台 `POST /api/anno/digest` 走 bridge 模式时，prompt 只被写到 `runtime/bridge/inbox/`，
**真正产出 JSON 的是执行 agent 自己**。所以：

```
执行 bridge 精读前，必须先加载本 skill（Skill 工具 → eb-anno-digest），
再按 `prompt.md` 的【摘要写法】构造 JSON（该规则正文已随 prompt 一起下发，直接可见）。
不加载 skill 直接写摘要 = 必然滑回基础条款罗列（2026-09-01 已实际踩坑）。
```

判断口诀：

```
if pending.items[0].scanned:   按 item.images 里的图片路径逐页 Read 读图识别
else:                          读 _txt_dump 里的 txt 文本
→ 构造 JSON 前先加载 eb-anno-digest skill
→ 按填空骨架填
→ 过一遍自检清单
→ POST /api/bridge/submit
```

**绝对路径**：`/api/anno/digest` 的 `files` 必须传绝对路径。传相对路径会按服务器 cwd
（EB-Agent）解析，导致全部"读取转储文本失败"，而任务仍显示 `done`（0 成功）——极易误判。

## 易错点（血泪版）

1. **同一份报告涉及多只 EB 时必须拆行**，且每只的换股价、代码、担保比例各不相同，
   不要复制粘贴后忘记改。
2. **换股价容易张冠李戴**：广东能源系的三只债（25粤能源EB 7.19、26粤能源KEB 12.48、
   26粤能源EB 12.88 标的其实是南网能源不是粤电力A）曾整片混淆。**逐只核对代码**。
3. **债券简称年份 vs 专户名年份**：26福达EB 的担保专户名仍写"25福达EB"（因为用的是
   2025 年的无异议函设立），别被专户名误导改错债券简称。
4. **日期统一取 PDF 的 CreationDate**，不用报告正文的"填报日"。PDF 生成日通常等于或
   略早于交易所披露日，差 0~2 个交易日，但能保证**全表口径一致**。
5. **数据分级标注**：A=交易所/公司公告原文，B=成品表历史记录，C=PDF 元数据推定。
   二手来源（B/C）必须在处理说明里写明，不要假装是一手。
6. **排除担保人财报**：如"中国船舶七一六所半年度财务报告（担保人）"是担保人的，
   不是发行人或标的公司公告，不收录。
7. **代码规则**：深交所私募 117xxx.SZ，上交所私募 137xxx.SH，上交所公募 132xxx.SH。
   代码写错等于整行报废。
8. **摘要不要回归基础条款**：写之前先问自己"这句是在讲风险/财务，还是在复述
   规模期限票面？"。后者一律删。

## 排版约定

宋体 11 号、不加粗、无填充、无边框、纯黑字、不自动换行、冻结首行。
列宽对齐成品表（A~I 依次为 11.2/10.9/21.9/20.0/11.7/16.5/20.9/47.3/149.7），
这样整理表可以**整行复制粘贴进成品大表**而不跑版。
